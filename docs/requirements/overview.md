# Обзор

Веб-платформа для ведения заказчиков по ремонтным и строительным проектам. Адаптивное веб-приложение с двумя ролями: администратор и заказчик.

Цель системы — единое пространство, где:

- администратор ведёт проекты, сметы, поступления от заказчика, акты, чеки, допработы, финансы и фото;
- заказчик видит только свои данные по проекту: ТЗ, смету, чеки, акты, допработы, финансы (только чтение), фото и сводные суммы по согласованной модели денег.

## Роли доступа

### Заказчик

Заказчик входит в личный кабинет и видит только свой объект и свои документы.

В личном кабинете заказчик **не** видит свои контакты (ФИО, телефон, e-mail) в шапке проекта — только данные объекта, прораба и бюджет (см. раздел «Шапка карточки»).

Вкладки в кабинете заказчика:

- ТЗ / проект;
- Смета;
- Чеки;
- Акты выполненных работ;
- Дополнительные работы;
- Финансы (счёт / оплата) — только просмотр;
- Фото.

### Администратор

Администратор имеет полный доступ ко всем заказчикам, объектам, документам и статистике.

Администратор может:

- создавать карточку заказчика;
- редактировать данные заказчика;
- создавать и редактировать проект;
- вести смету;
- прикреплять документы и фотографии;
- вносить поступления от заказчика и вести финансы проекта;
- отмечать оплату чеков (в т. ч. оплату заказчиком напрямую), когда депозита на материалы не хватает;
- формировать акты;
- добавлять допработы;
- смотреть общую статистику по всем проектам.

## Структура системы

### Раздел «Заказчики»

Список всех заказчиков в виде таблицы или карточек.

В списке предусмотреть:

- ФИО;
- адрес;
- статус проекта;
- сумма сметы (работ, с учётом допработ, включённых в общий бюджет);
- поступило от заказчика всего;
- освоено (потрачено) всего;
- остаток на руках у подрядчика;
- к доплате сейчас;
- дата начала проекта;
- дата последнего обновления.

Функции:

- поиск по ФИО, адресу, номеру проекта;
- фильтр по статусу проекта;
- сортировка;
- кнопка «Создать заказчика»;
- переход в карточку объекта.

### Карточка заказчика / проекта

Внутри карточки — основная информация о клиенте и навигация по вкладкам.

Шапка карточки **различается по ролям** (отдельные визуальные блоки с заголовками, не один общий список полей).

**Заказчик** видит три блока:

1. **Объект** — название проекта, адрес, статус проекта, дата старта.
2. **Прораб** — ФИО, телефон и e-mail менеджера проекта (пользователь с ролью администратор, назначенный через `Project.managerId`; телефон хранится в `User.phone`).
3. **Бюджет** — смета работ, поступило, освоено, остаток на руках, к доплате сейчас, нужно ещё до конца сметы (по работам). Цифры сгруппированы парами для быстрого чтения: смета ↔ освоено, поступило ↔ остаток, к доплате ↔ нужно ещё.

Собственные контакты заказчика (ФИО, телефон, e-mail) в его шапке **не показываются**.

**Администратор** видит:

1. **Объект** — те же поля, что у заказчика.
2. **Заказчик** — ФИО, телефон, e-mail.
3. **Бюджет** — те же показатели и та же группировка пар.
4. Опционально короткая строка «Ответственный: …» (имя назначенного менеджера) без отдельного блока про себя.

Состав вкладок — в [функциях](./features.md).

## Критерии приёмки

Система соответствует ТЗ, если:

- реализованы две роли с корректным разграничением доступа;
- заказчик видит только свои данные;
- администратор может управлять всеми проектами;
- смета поддерживает формулы, редактирование строк, скрытие и добавление позиций;
- в ключевых вкладках можно прикреплять фото и документы;
- чеки разделяются по статусам оплаты; оплата чека и списание с депозита на материалы — одни и те же данные, без дублирующего ввода;
- подписанные акты списывают сумму из кошелька «Работы»; материалы учитываются только через чеки;
- дополнительные работы ведутся отдельно; согласованные учитываются в финансах по правилам «включить в общий бюджет»;
- вкладка «Финансы» показывает поступления, кошельки и сальдовую ведомость, рассчитанную из данных;
- в списке заказчиков и шапке проекта суммы соответствуют модели: смета, поступило, освоено, остаток, к доплате;
- статистика администратора считает поступления, освоение и к доплате по той же модели;
- система работает адаптивно;
- доступ к данным и файлам защищён;
- реализовано логирование и базовые меры безопасности.
