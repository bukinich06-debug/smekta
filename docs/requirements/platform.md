# Платформа

Нефункциональные требования, стек, сущности базы и интеграции. Состав экранов — в [функциях](./features.md).

Слои приложения и работа с Prisma — в [README](../../README.md) и [AGENTS.md](../../AGENTS.md).

## Производительность

Карточки проектов, вкладки и файлы открываются быстро и при накоплении данных. Содержимое файлов в таблицы базы не кладём.

Требования:

- быстрое открытие карточек и списков;
- постраничная загрузка при больших объёмах данных;
- оптимизация таблиц и фильтров;
- кеширование там, где это уместно;
- сжатие изображений при загрузке при необходимости.

## Безопасность

В системе хранятся персональные и финансовые данные.

Требования:

- HTTPS для всех соединений;
- авторизация по email и паролю;
- восстановление пароля;
- разграничение ролей: заказчик / администратор;
- серверная проверка прав доступа для каждого запроса;
- MFA желательно сделать обязательной для администраторов и доступной для заказчиков;
- ограничение количества попыток входа;
- журнал действий пользователей;
- приватное хранение файлов;
- защита от XSS, SQL injection и broken access control.

## Надёжность и сопровождение

- отдельные окружения development / staging / production;
- резервное копирование БД и файлов;
- логирование ошибок;
- мониторинг доступности;
- возможность масштабирования при росте числа проектов и файлов.

## Стек

Приложение целиком на Next.js: интерфейс и серверная логика в одном проекте, хостинг на Vercel. База — PostgreSQL.

| Компонент | Решение | Назначение |
| --- | --- | --- |
| Приложение | Next.js, React, TypeScript | Кабинет, админка, серверные сценарии |
| Хостинг приложения | Vercel | Развёртывание |
| База данных | PostgreSQL | Пользователи, проекты, сметы, поступления, чеки, акты, метаданные файлов |
| Где лежит база | не выбрано, вероятный вариант — Neon | Хостинг PostgreSQL |
| Файлы | не выбрано | Фото, чеки, акты, документы |

### Приложение

- Next.js, React, TypeScript;
- хостинг на Vercel;
- адаптивный интерфейс;
- таблицы со строками, редактированием, скрытием позиций и фильтрами;
- загрузка и предпросмотр документов и изображений;
- русскоязычный интерфейс.

Серверная часть живёт в том же Next.js-приложении:

- серверная валидация данных;
- серверная проверка прав для каждого запроса;
- история изменений;
- логирование ошибок и критичных действий пользователей.

### База данных

- PostgreSQL;
- где размещать базу, пока не решено; вероятный вариант — Neon;
- сущности и связи между проектами, пользователями, сметами, поступлениями от заказчика, чеками, актами, допработами, файлами и фото;
- остатки кошельков «Работы» / «Материалы» и сальдовая ведомость — производные показатели (вычисляются из поступлений, актов, чеков, допработ и переводов, отдельный ручной журнал не ведётся);
- таблица аудита действий;
- индексы для поиска и фильтров.

Схему применяем через Prisma: `npm run db:push` и `npm run db:generate`, без миграций.

### Аутентификация

Способ входа ещё не выбран. К моменту реализации нужно:

- вход по email и паролю;
- восстановление пароля;
- ролевой доступ;
- ограничение попыток входа;
- желательно MFA для администраторов;
- безопасное управление сессиями.

### Хранение файлов

Где хранить файлы, пока не решено. Содержимое файлов в таблицы базы не кладём.

Пока место не выбрано, фиксируем только доступ:

- без публичной прямой ссылки на файл;
- выдача файла только после проверки прав.

## Предварительная структура данных

Минимальный набор сущностей на этапе проектирования базы:

- users;
- roles;
- clients;
- projects;
- estimates;
- estimate_items;
- project_inflows (поступления от заказчика: дата, сумма, назначение «аванс на работы» / «депозит на материалы», комментарий, автор);
- wallet_transfers (явные переводы между кошельками проекта);
- receipts (чеки на материалы, статус и суммы оплаты, в т. ч. зачёт из депозита);
- acts;
- extra_works (в т. ч. флаг «включить в общий бюджет»);
- files;
- photos;
- activity_logs.

Производные при чтении (отдельные таблицы не обязательны, если логика расчёта однозначна):

- остатки кошельков «Работы» и «Материалы»;
- строки сальдовой ведомости;
- сводные показатели проекта: поступило, освоено, остаток, к доплате, нужно ещё до конца сметы.

## Интеграции и расширение

Часть интеграций может не войти в первую версию, но архитектура должна их допускать:

- email-уведомления;
- SMS или мессенджеры;
- экспорт в Excel и PDF;
- CRM;
- бухгалтерские системы;
- электронная подпись документов;
- внешние API и webhook.
