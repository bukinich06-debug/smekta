# Функции

Вкладки карточки проекта, общие вложения, статистика администратора и требования к интерфейсу. Роли и шапка карточки — в [обзоре](./overview.md).

Порядок вкладок в карточке проекта (админ и заказчик): ТЗ / проект → Смета → Чеки → Акты выполненных работ → Дополнительные работы → **Финансы** → Фото.

## Модель денег проекта

Согласованные правила учёта (без двойного учёта):

- **Работы** — смета и акты: стоимость работ задаётся сметой; освоение по работам — только подписанные акты (статус «подписан»), не отдельная отметка «выполнено» у строк сметы.
- **Материалы** — только через вкладку «Чеки»: в смете материалы могут быть справочно, но списание денег по материалам идёт по чекам, не по смете.
- **Поступления** — деньги от заказчика вносятся на вкладке «Финансы» в один из двух кошельков; акты и чеки сами по себе поступления не создают.
- **Допработы** — отдельные начисления; в освоение и «к доплате» попадают только **выполненные** (после согласования); списание из кошелька «Работы» — только если включена галка «включить в общий бюджет». В смету работ входят согласованные и выполненные допработы с этой галкой.

Показатели **поступило**, **освоено**, **остаток**, **к доплате**, **нужно ещё до конца сметы** в шапке проекта, в списке заказчиков и на вкладке «Финансы» считаются по этой модели, а не как «оплачено = сумма оплат по чекам». Сводные суммы **одинаковы** у администратора и заказчика (учитываются все позиции и допработы); видимость влияет только на списки во вкладках «Смета» и «Допработы». В шапке карточки бюджетные цифры у обеих ролей сгруппированы парами (смета ↔ освоено, поступило ↔ остаток, к доплате ↔ нужно ещё); состав блоков шапки по ролям — в [обзоре](./overview.md).

## Вкладка «ТЗ / Проект»

Раздел для хранения технического задания и проектной информации.

Должно быть:

- текстовое описание ТЗ;
- возможность редактирования текста;
- прикрепление файлов;
- прикрепление фотографий;
- загрузка PDF, DOCX, XLSX, JPG, PNG;
- дата загрузки;
- автор загрузки;
- история изменений.

Желательно:

- версии документов;
- пометка «актуальная версия».

## Вкладка «Смета»

Ключевой раздел: редактируемые строки и прозрачная стоимость для клиента.

Таблица с редактируемыми строками и формулами.

Колонки сметы:

- №;
- наименование позиции;
- единица измерения;
- количество;
- цена за единицу;
- сумма;
- комментарий;
- статус позиции (черновик / согласовано);
- видимость для заказчика.

Отдельной отметки «выполнено» у позиции сметы нет: позиция считается выполненной, если входит в акт в статусе «подписан». Акты в статусе «отправлен» отображаются как ожидающие подписи и на кошелёк «Работы» не списываются.

Формулы:

- сумма по строке = количество × цена за единицу;
- итог по разделу;
- итог по всей смете;
- отдельный итог по скрытым и видимым позициям при необходимости;
- пересчёт итогов при изменении количества или цены.

Функции:

- добавление новой позиции;
- удаление позиции;
- редактирование любой позиции;
- скрытие позиции из отображения для заказчика;
- показ скрытых позиций в админке;
- группировка по разделам, например: демонтаж, черновые работы, чистовые работы, материалы;
- ручная корректировка наименования, единицы измерения, количества, цены;
- кнопка «добавить раздел»;
- кнопка «добавить позицию»;
- экспорт сметы в PDF / Excel;
- отображение итоговой суммы.

Отдельно предусмотреть:

- видимость «для заказчика» / «только для администратора»;
- лог изменения сметы: кто, когда и что изменил;
- возможность отмечать позицию как «согласовано».

## Вкладка «Чеки»

Учёт расходов на **материалы** и подтверждающие документы. Оплата фиксируется здесь один раз: статус оплаты на вкладке и списание с кошелька «Материалы» на вкладке «Финансы» берутся из одних данных, дублирующего ввода нет.

Структура раздела:

- список чеков;
- фильтрация по статусу: оплачено / недоплачено / ожидает оплаты;
- привязка чека к проекту и, при необходимости, к разделу сметы (справочно).

Поля записи:

- дата;
- наименование платежа;
- сумма чека;
- сумма, покрытая из депозита на материалы;
- сумма, оплаченная иным способом (например, заказчиком напрямую);
- остаток к оплате;
- статус оплаты;
- комментарий;
- прикреплённый файл или фото чека.

Правила оплаты и депозита:

- при создании или изменении чека, если на депозите «Материалы» достаточно средств, чек автоматически считается оплаченным из депозита;
- если средств не хватает — с депозита списывается доступная часть, остаток ждёт, пока администратор не отметит оплату (в т. ч. оплату заказчиком напрямую);
- если депозита нет — чек не списывается с кошелька, пока администратор не отметит оплату;
- при изменении суммы или удалении чека зачёт из депозита пересчитывается (средства возвращаются на депозит).

Функции:

- загрузка фото чеков;
- загрузка PDF-файлов;
- отметка оплаты администратором (полностью / частично), когда депозита недостаточно;
- автоматический расчёт остатка и статуса;
- сортировка по дате;
- просмотр истории оплат (каждая оплата — дата, сумма, способ: зачёт из депозита или прямая, автор).

## Вкладка «Акты выполненных работ»

Хранение актов по этапам.

Должно быть:

- список актов;
- дата акта;
- номер акта;
- этап работ;
- сумма по акту;
- статус: черновик / отправлен / подписан;
- прикрепление файла акта;
- прикрепление фото к акту;
- комментарий.

Функции:

- создание акта вручную;
- выбор позиций из сметы для акта;
- автоматическая подстановка суммы выбранных работ;
- выгрузка акта в PDF;
- история подписания и загрузки.

Финансы:

- при переводе акта в статус «подписан» сумма акта списывается из кошелька «Работы» (поступление «Аванс на работы»);
- акт в статусе «отправлен» показывается как ожидающий подписи и не списывается;
- отрицательный остаток кошелька «Работы» означает сумму **к доплате** по работам, это не ошибка данных.

## Вкладка «Дополнительные работы»

Дополнительные работы фиксируются отдельно от основной сметы.

В разделе предусмотреть:

- список допработ;
- дата;
- описание;
- единица измерения;
- количество;
- цена;
- сумма;
- статус согласования;
- видимость для заказчика;
- прикреплённые фото и документы.

Функции:

- добавить допработу;
- редактировать;
- скрыть / показать заказчику;
- отметить как согласованную;
- отметить как выполненную (после согласования);
- включить в общий бюджет проекта;
- выгрузить список допработ отдельно.

Галка «включить в общий бюджет» (для согласованных и выполненных допработ):

- **выключена** — после выполнения сумма в **к доплате** отдельной строкой (например, −25 000 ₽); ни из какого кошелька не списывается, смету работ не увеличивает;
- **включена** — увеличивает смету работ (с момента согласования); списание из кошелька «Работы» — только после отметки «выполнено» (как подписанный акт).

## Вкладка «Финансы»

Рабочее название вкладки — «Финансы»; допустим вариант «Счёт / оплата». Располагается **после** вкладки «Дополнительные работы». Доступ: администратор — полный; заказчик — только чтение (поступления, кошельки, ведомость, сводные цифры).

### Сводка «Бюджет проекта» (вверху вкладки)

- сумма сметы работ (с учётом допработ, включённых в общий бюджет);
- поступило от заказчика всего;
- освоено (потрачено) всего;
- остаток на руках у подрядчика (сумма остатков двух кошельков);
- к доплате сейчас (в т. ч. допработы без галки бюджета и недостача по кошельку «Работы»);
- нужно ещё до конца сметы (по работам): смета работ (с допработами, включёнными в общий бюджет) минус поступления на кошелёк «Работы» (с учётом переводов).

### Два кошелька

Под сводкой — остатки по кошелькам:

| Кошелёк | Пополнение | Списание |
| --- | --- | --- |
| **Работы** | поступления с назначением «Аванс на работы» | подписанные акты; **выполненные** допработы с галкой «включить в общий бюджет» |
| **Материалы** | поступления с назначением «Депозит на материалы» | зачёт из депозита по чекам (автоматически); прямая оплата заказчиком кошелёк не уменьшает |

Перевод между кошельками — только **явной записью** администратора: минус из одного кошелька, плюс в другой (две связанные строки в ведомости).

### Блок «Поступления» (слева)

Администратор вносит деньги, полученные от заказчика:

- дата;
- сумма;
- назначение: «Аванс на работы» или «Депозит на материалы»;
- комментарий;
- автор записи.

Для каждого кошелька показывать текущий остаток. Заказчик видит список поступлений и остатки без возможности редактирования.

### Сальдовая ведомость (справа)

Хронологическая лента **всех** денежных движений по проекту с **текущим остатком** (по выбранному кошельку или сводно — по решению интерфейса) после каждой строки. Ведомость **не ведётся вручную**, а вычисляется из данных системы.

Типы движений:

- поступления от заказчика (**+** в соответствующий кошелёк);
- подписанные акты (**−** из кошелька «Работы»);
- оплаченные чеки (**−** из кошелька «Материалы»);
- выполненные допработы (**−** из «Работы», если включены в бюджет; иначе в «к доплате»); согласованные, но не выполненные — ожидание без списания;
- переводы между кошельками (**−** / **+**).

Акты «отправлен» в ведомости как списание не участвуют (допустима пометка «ожидает подписи» вне ленты или в справочном виде).

### Пример расчёта

Смета работ (с допработами в бюджете) — **900 000 ₽**. Заказчик внёс **1 200 000 ₽**: 700 000 ₽ — аванс на работы, 500 000 ₽ — депозит на материалы. Подписаны акты на **450 000 ₽**, чеки на **380 000 ₽**, согласованная допработа **25 000 ₽** без галки «включить в общий бюджет».

| Показатель | Значение |
| --- | --- |
| Поступило | 1 200 000 ₽ |
| Освоено | 855 000 ₽ (450 000 + 380 000 + 25 000) |
| Остаток у подрядчика | 370 000 ₽ (работы 250 000 + материалы 120 000) |
| К доплате сейчас | 25 000 ₽ |
| Нужно ещё до конца сметы (работы) | 200 000 ₽ (900 000 − 700 000 поступлений на «Работы») |

## Вкладка «Фото»

Фото прогресса проекта: отдельный раздел и загрузка внутри связанных вкладок.

Требования:

- загрузка фотографий в каждую вкладку и в общий фотораздел;
- предпросмотр фото;
- увеличение по клику;
- подпись к фото;
- дата загрузки;
- сортировка по дате;
- привязка к этапу, разделу или документу;
- загрузка нескольких фото сразу;
- удаление фото;
- альбомы: до начала работ / процесс / завершение / скрытые фото.

## Статистика

Раздел доступен только администратору. Это сводка по всем объектам.

В статистике отобразить (агрегаты по той же модели денег, что в карточке проекта):

- общее количество проектов;
- активные проекты;
- завершённые проекты;
- общую сумму смет работ;
- поступило от заказчиков всего;
- освоено всего;
- остаток на руках у подрядчика (сумма по проектам);
- к доплате сейчас (сумма по проектам);
- количество неоплаченных или частично оплаченных чеков;
- объём согласованных дополнительных работ;
- недавние изменения по проектам.

Желательные визуальные элементы:

- карточки KPI;
- графики по поступлениям, освоению и к доплате;
- фильтр по периоду;
- фильтр по статусу проекта.

## Работа с вложениями

Во вкладках ТЗ, смета, чеки, акты, дополнительные работы и фото можно прикреплять фотографии и документы. Доступ к файлам проверяет сервер, не только интерфейс.

Общие требования:

- поддержка форматов JPG, PNG, PDF, XLSX, DOCX;
- предпросмотр изображений;
- скачивание файлов;
- автор и дата загрузки;
- ограничение размера файла;
- множественная загрузка;
- приватный доступ только для уполномоченных пользователей.

**Реализовано (первая итерация):** вкладка «Чеки» — загрузка JPG, PNG и PDF (до 10 МБ) в Vercel Blob, хранение метаданных в модели `File`, вложения к чеку и опционально к записи оплаты; администратор загружает и удаляет, заказчик видит вложения своего проекта; предпросмотр изображений и скачивание через защищённый API.

## Интерфейс

- адаптивная работа на desktop, tablet и mobile;
- русскоязычный интерфейс;
- спокойный профессиональный вид;
- левая боковая или верхняя навигация в админке;
- хлебные крошки или понятный маршрут внутри карточки проекта;
- таблицы с сортировкой и фильтрацией;
- быстрые кнопки добавления документов, позиций и фото;
- статусы, выделенные цветом;
- уведомления о сохранении, загрузке, ошибках и изменениях.
